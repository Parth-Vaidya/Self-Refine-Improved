# Phase 4 Evaluation Plan: Comparative Performance, Telemetry, and Personalization Assessment

## Executive Summary

This document outlines a practical, low-overhead evaluation plan for a student research project based on `Self-Refine-Improved`. It assesses:
1. **Efficiency trade-offs:** Standard (single-pass) vs. Self-Refine (iterative) generation in terms of latency, token consumption, and API call frequency.
2. **Quality impact:** Candidate refinement effectiveness and iterative convergence.
3. **Personalization adherence:** The degree to which responses adhere to user style preferences stored in `user_profile.json`.

---

## 1. Architectural Inspection & Telemetry Audit

An audit of the existing codebase reveals distinct capabilities across the **benchmark pipeline** vs. the **interactive chat pipeline**:

| Metric / Capability | Benchmark Pipeline (`src/experiment.py`, `src/report.py`) | Interactive Chat Pipeline (`src/chat_pipeline.py`, `src/chat_app.py`) | Status for Evaluation |
|---|---|---|---|
| **Input & Output Tokens** | Recorded per call (`prompt_tokens`, `completion_tokens`, `total_tokens` via `observed_call()`). | Reported by raw backend response dicts, but not logged or persisted to `chats/*.txt`. | **Partially Available** (Built into backend adapters; not persisted in interactive chat files). |
| **Call Count & Costs** | `observed_call()` tracks call counts and estimates USD cost based on `config["prices"]`. | Not tracked or aggregated across interactive turns. | **Partially Available** (Cost calculation logic exists in `prompt_lib/experiment.py`). |
| **Latency / Response Time** | `time.perf_counter()` records per-call and end-to-end `latency_seconds` in experiment records. | Not recorded in `chats/*.txt`. | **Available in Benchmark**; missing from chat session files. |
| **Standard vs. Self-Refine Comparison** | Benchmark A (1-pass) vs. Benchmark B (iterative) executes identical tasks and compares scores. | Users choose per-turn (`standard` vs `self_refine`), but no side-by-side automated comparison harness exists. | **Framework exists**; automated side-by-side comparative runner needed. |
| **Personalization Evaluation** | Not present in legacy benchmarks. | Implemented via `load_personalization_instruction()` in `src/chat_pipeline.py`. | **Ready for Evaluation**; requires standardized evaluation prompt suite. |

## 2. Evaluation Objectives

1. **Trade-Off Analysis (Standard vs. Self-Refine):**
   - Quantify token usage multiplier ($N_{\text{self-refine}} / N_{\text{standard}}$).
   - Quantify latency cost ($\Delta t$).
   - Determine when refinement yields tangible improvements versus unnecessary token consumption.
2. **Personalization Adherence:**
   - Measure whether the system correctly applies enabled preferences (`prefers_step_by_step`, `prefers_concise_answers`, `prefers_simple_code`, `prefers_examples`) without degrading factual accuracy.
3. **Robustness & Rate-Limit Impact:**
   - Verify that automated retry pacing (`GROQ_RESUME_ON_RATE_LIMIT`) prevents quota thrashing during evaluations.

---

## 3. Evaluation Dimensions & Metrics

### 3.1 Efficiency Metrics (Quantitative)
- **Prompt Tokens ($T_{\text{in}}$):** Tokens consumed by system instructions, conversation history, and prompts.
- **Completion Tokens ($T_{\text{out}}$):** Tokens generated by initial drafts, feedback critiques, and refinements.
- **Total Cost Estimate ($C$):** Calculated using Groq Qwen rates (or standard token price basis).
- **Latency ($\tau$):** Wall-clock time in seconds from user query submission to final displayed answer.
- **API Call Overhead:** Number of network round-trips (Standard: 1 call; Self-Refine: 2 to 4 calls).

### 3.2 Quality & Personalization Metrics
- **Self-Refine Feedback Score:** Critique score progression (e.g. initial score vs. final score out of 10).
- **Style Adherence Score (1–5 scale):**
  - Evaluates whether the generated response honors active profile constraints (e.g., did a request for `prefers_step_by_step` produce enumerated sequential steps?).
- **Factuality & Coherence (1–5 scale):**
  - Confirms that stylistic personalization did not omit essential information or hallucinate facts.

## 4. Evaluation Methodology for Student Research

To keep the study manageable and stay within budget/quota limits (e.g. Groq free tier / request budget ledger):

### 4.1 Test Dataset (20 Curated Prompts)
Create a lightweight evaluation set across 4 distinct categories (5 prompts each):
1. **Conceptual Theory:** e.g., *"Explain Newton's third law with action-reaction pairs."*
2. **Algorithmic / Code:** e.g., *"Write a Python function to find the longest palindromic substring."*
3. **Problem-Solving / Math:** e.g., *"Solve the recurrence relation T(n) = 2T(n/2) + n."*
4. **General Technical QA:** e.g., *"What is the difference between TCP and UDP headers?"*

### 4.2 Experimental Conditions
For each prompt, test under four controlled conditions:
- **Condition 1 (Baseline Standard):** No personalization, Standard 1-pass mode.
- **Condition 2 (Baseline Self-Refine):** No personalization, Self-Refine mode (attempts=2).
- **Condition 3 (Personalized Standard):** Active preference (e.g., `prefers_concise_answers` or `prefers_step_by_step`), Standard mode.
- **Condition 4 (Personalized Self-Refine):** Active preference, Self-Refine mode.

Total executions: 20 prompts $\times$ 4 conditions = 80 runs (well within the local 700-request ledger limit).

## 6. What is Available vs. What Needs to be Implemented

### Already Available (Reuse as-is):
- `observed_call()` in `prompt_lib/experiment.py` (tracks tokens, stages, latency, cost basis).
- `ChatResponsePipeline` in `src/chat_pipeline.py` (handles both Standard and Self-Refine with personalization).
- `load_personalization_instruction()` in `src/chat_pipeline.py` (reads enabled preferences from `user_profile.json`).
- `GroqAPIWrapper` with automatic rate-limit cooldown and recovery.
- `src/report.py` (formats telemetry into clean Markdown summaries).

### Missing / What to Build in Phase 4:
- An offline, standalone evaluation script (`src/evaluator.py` or `evaluate_modes.py`).
- A curated test prompt dataset (`evaluations/eval_prompts.json`).
- An evaluation report generator that aggregates metrics into tables and markdown graphs.

---

## 7. Recommended Implementation Sequence for Phase 4

Keep the implementation minimal, non-invasive, and clean:

1. **Step 1: Test Prompts (`evaluations/eval_prompts.json`):**
   - Define the 20 benchmark questions and target profile presets.
2. **Step 2: Standalone Evaluation Runner (`src/evaluator.py`):**
   - Reuses `ChatResponsePipeline`.
   - Wraps calls in `prompt_lib.experiment.observed_call()` or records `time.perf_counter()` and token counts directly from the backend output.
   - Executes the 4 conditions per prompt.
   - Saves results incrementally to `evaluations/phase_4_results.jsonl`.
3. **Step 3: Summary Analysis Script (`src/eval_report.py`):**
   - Reads `phase_4_results.jsonl`.
   - Computes:
     - Average latency: Standard vs. Self-Refine.
     - Average token consumption: Standard vs. Self-Refine.
     - Refinement delta ($\Delta \text{Score}$).
     - Preference adherence rate (% of responses following enabled profile rules).
   - Generates a concise markdown report `PHASE_4_EVALUATION_REPORT.md` suitable for course submission or presentation.
